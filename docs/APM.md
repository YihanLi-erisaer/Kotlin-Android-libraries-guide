4.  **实战风险预警**：增加了国内访问 Firebase 看板难、Bugly 维护频率降低等实操细节。

## 🛠️ APM 治理红线与技术准则

为了确保 APM 库不成为项目的性能负担，建议在集成时遵循以下治理准则：

### 1. 构建性能治理 (Build Safety)
*   **红线**：禁止在 Debug 环境下开启编译期插桩。
*   **准则**：对于 **Sentry**、**火山引擎** 等涉及 ASM 插桩的库，必须在 `build.gradle.kts` 中通过开关控制。仅在 `Release` 或 `Staging` 变体中启用插桩，避免日常开发增量编译变慢（ASM 插桩通常增加 10s-30s 构建耗时）。

### 2. 隐私合规治理 (Privacy Compliance)
*   **红线**：严禁在用户同意隐私协议前调用任何初始化代码。
*   **准则**：
    *   所有 APM 库必须支持 **延迟初始化**。
    *   **SLS** 和 **Firebase** 默认会有部分静默采集行为，需在 `AndroidManifest.xml` 中通过 `meta-data` 显式禁用其自动启动，改为手动按序初始化。

### 3. 性能监控深度 (Monitoring Depth)
*   **原则**：选型应优先考虑支持 **Kotlin 协程追踪** 和 **Compose 重组监控** 的库。
*   **实战建议**：
    *   如果应用大量使用 Compose，优先选 **Sentry**，它能自动捕获哪些 Composable 函数导致了多余的重组。
    *   如果应用涉及复杂的 Native (C++) 逻辑，优先选 **Bugly** 或 **火山引擎**，其对 Native 堆栈的解析更符合国内机型现状。

### 4. 符号表自动化 (Symbolication)
*   **治理要求**：必须在 CI/CD 流程中实现混淆映射表（Mapping.txt）和符号表（SO Symbol）的**自动化上传**。
*   **痛点预警**：Bugly 的插件对新版 AGP (8.0+) 兼容性不佳，可能需要手写脚本通过 Curl 调用其 API 进行上传；Sentry 和 Firebase 官方插件支持最为完善。
