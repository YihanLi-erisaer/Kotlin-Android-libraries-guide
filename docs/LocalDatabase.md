### 数据库工程化治理红线 (Database Governance)

数据库是 App 的“持久化中枢”，一旦发生数据退化（Schema Regression）或损坏，后果往往是灾难性的。建议增加以下治理准则：

#### A. 编译期校验红线 (Compile-time Verification)
*   **准则**：禁止使用不带编译期 SQL 校验的原始 SQLite 封装。
*   **要求**：必须使用 **Room** 或 **SQLDelight**。
*   **理由**：在代码运行到该处才报错（如字段名拼错）是低级架构错误，必须通过编译期生成的类来保证 SQL 语法的正确性。

#### B. 架构隔离与线程治理
*   **红线**：禁止在主线程执行任何数据库操作（会导致明显的丢帧或 ANR）。
*   **要求**：
    *   **Room/SQLDelight**：必须返回 `Flow` 或 `Suspend` 函数。
    *   **治理策略**：在 Repository 层强制指定 `Dispatchers.IO`。

#### C. 数据库迁移治理 (Migration Governance)
*   **准则**：所有数据库 Schema 的变更必须伴随 **Version 递增** 和 **Migration 测试**。
*   **红线**：禁止在正式环境使用 `fallbackToDestructiveMigration()`（除非是纯缓存数据库）。
*   **治理对策**：推荐在 CI/CD 流程中加入 **Room Schema 导出校验**，确保混淆后的库依然能识别 Schema。

#### D. 加密治理策略
*   **准则**：明文数据库禁止存储用户密码、Token 或生物识别哈希。
*   **选型**：若需全库加密，推荐使用 **Room + SQLCipher (SupportFactory)**。注意：开启加密后，数据库性能通常会下降 20%-30%，需在 APM 中重点监控 `db_query` 耗时。

#### E.数据库连接数治理 (Connection Governance)
*   **红线**：严禁在循环或高频操作中反复打开/关闭数据库连接。
*   **要求**：数据库实例（RoomDatabase / SQLDelight Database）必须作为 单例 通过 DI（Hilt/Koin）注入。
*   **并发治理**：SQLite 默认不支持并发写入。在多线程大量写入时（如批量同步数据），必须使用 withTransaction 或 transaction 块，这不仅能保证原子性，还能将写入性能提升 10-100 倍。

### 总结：数据库选型决策路径

1.  **你是纯 Android 项目，且需要快速上线？**
    *   👉 **Room** (配合 KSP，编译比以前快得多)。
2.  **你是 KMP 项目，且团队 SQL 水平较高？**
    *   👉 **SQLDelight** (最纯正的跨平台 SQL 体验)。
3.  **你需要处理海量数据（如：离线地图、上百万条通话记录）？**
    *   👉 **ObjectBox** (性能断层领先)。
4.  **你正在从 Realm (Java) 迁移到现代 Kotlin 架构？**
    *   👉 使用 **Realm Kotlin SDK**，它在 Compose 中的表现已经大幅提升。
5.  **你的数据涉及金融资产，有极其严格的合规要求？**
    *   👉 **Room + SQLCipher**。
