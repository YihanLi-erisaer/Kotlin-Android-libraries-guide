## 动画选型实战建议

### 1. 决策模型：我该选哪个？
*   **Case A：基础 UI 交互（如按钮缩放、列表淡入、导航转场）**
    *   **选型**：`Compose Animation` (内置)。
    *   **理由**：性能最优，支持 **Shared Element (共享元素)** 实现丝滑的跨页面图片/文字过渡。
*   **Case B：精美动效展示（如加载动画、节日气氛动效）**
    *   **选型**：**Lottie**。
    *   **理由**：设计师资源丰富，Android/iOS/Web 三端逻辑高度统一。
*   **Case C：重度动效与高性能需求（如礼物动效、游戏化特效）**
    *   **选型**：**PAG**。
    *   **理由**：相比 Lottie，PAG 采用了视频序列帧结合矢量化的方案，在复杂动效下 CPU 占用极低，且支持 AE 中的所有滤镜特效。
*   **Case D：高度交互的动效（如随手指滑动的角色动画、状态流转逻辑）**
    *   **选型**：**Rive**。
    *   **理由**：Rive 允许设计师在编辑器里内置“状态机”，开发者只需通过代码触发 `fireTrigger("hit")`，动画的流转衔接由引擎自动完成。

### 2. 性能与体积红线
*   **体积警示**：**Rive** 和 **PAG** 均包含 C++ 渲染引擎（.so 文件）。如果项目对 APK 体积极其敏感（如 10MB 以内的轻量级应用），应优先使用 **Compose 内置动画** 或 **Lottie**。
*   **渲染红线**：
    *   **Lottie**：主要在 CPU 侧计算路径，路径越多越卡顿。
    *   **PAG/Rive**：直接在 GPU 侧渲染，性能瓶颈通常在于显存占用而非计算。

### 3. 调试与治理点
*   **动画预览**：强烈建议利用 Android Studio 的 **Animation Preview** 工具。它可以像视频播放器一样拉动进度条查看每一帧的 Compose 状态，是调试交互动画的神器。
*   **资源治理**：Lottie 资源建议通过 **网络下发 + 内存缓存** 治理，避免内置大量 JSON 导致 APK 虚胖。
*   **版本适配**：MotionLayout 在 Compose 中的支持由 `androidx.constraintlayout:constraintlayout-compose` 提供，确保版本在 1.1.0 以上以获得最佳稳定性。
