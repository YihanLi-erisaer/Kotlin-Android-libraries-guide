### 状态管理工程化治理红线 (Status Governance)

状态管理是 UI 闪烁和 Bug 滋生的根源，必须建立以下治理准则：

#### A. 单向数据流 (UDF) 强制红线
*   **准则**：**UI 层对状态必须是“只读”的。**
*   **红线**：严禁在 Compose UI 内部通过 `state.value = ...` 直接修改 ViewModel 状态。
*   **要求**：ViewModel 必须暴露不可变的 `StateFlow` 或 `State`，修改状态必须通过显式的 `Action/Event` 函数。

#### B. 状态收集性能红线 (Lifecycle Safety)
*   **准则**：Compose 消费 Flow 必须具备 **生命周期感知**。
*   **红线**：禁止直接使用 `flow.collectAsState()`（这会导致 App 进入后台时仍持续采集，造成资源浪费）。
*   **对策**：必须使用 **`collectAsStateWithLifecycle()`**。

#### C. “一次性事件”治理 (Side Effects)
*   **准则**：Toast、跳转、弹窗属于“事件”，不是“状态”。
*   **红线**：严禁将事件直接放入 `StateFlow` 中（会导致配置变更/旋转屏幕后重复触发）。
*   **推荐方案**：
    *   使用 **Orbit MVI 的 sideEffect** 通道。
    *   使用 `Channel(capacity = Channel.BUFFERED)`。

#### D. 状态恢复 (Process Death) 治理
*   **准则**：核心业务状态（如搜索词、表单草稿）必须支持进程重启恢复。
*   **方案**：
    *   ViewModel 中使用 `SavedStateHandle`。
    *   Compose UI 内部使用 `rememberSaveable`。

### 选型决策决策树

1.  **你需要做 iOS/Android 逻辑共享 (KMP)？**
    *   👉 **AndroidX ViewModel (KMP 版)** + **StateFlow**。
    *   如需更严谨的 MVI，加配 **Orbit MVI**。
2.  **你是纯 Android 复杂业务，且被“进程重启数据丢失”困扰？**
    *   👉 **Mavericks**。它的状态持久化和异步状态处理（`Async<T>`）是目前工业界最成熟的。
3.  **你追求极致的声明式代码，觉得写 Flow 转换太麻烦？**
    *   👉 **Molecule**。用写 Compose 的方式来写业务逻辑。
4.  **你只是在写简单的 UI 内部交互（如开关开启、下拉展开）？**
    *   👉 直接使用 **Compose State (`mutableStateOf`)**。
